My information was very basic (x,y,z and 1,2,3), which highlighted the process in which it was displayed for me. In CSV format, the data is at its most basic form, just a bit more complex than in plaintext. In my case, it wasn't different at all from plain text, but CSV stylings can draw data from excel spreadsheets. One gripe about CSV compared to the dictionary and object formatting that I used is that it could not draw a value from a placeholder string, giving the output of only x, y, z; not 1, 2, 3. As for the dictionary styling, I feel it is the most easily accessible for other people to both read and write. It does not require a lengthy setup, and functions as a simple library/list both in code and output. As previously stated, the x y and z values show as their numerical correlations, the biggest difference from CSV. Lastly, I wanted to add object styling to see the differences it had compared to dictionary format. While their output looks the same, their inner workings are certainly different. Object styling requires you to set up a class, then creates a function within which you define its variables. Then, you call the function, giving x, y and z their values separately. This format seems more database-oriented. It would be best in a larger program where the function is called multiple times, and it has the ability to use different given values on subsequent callings.
